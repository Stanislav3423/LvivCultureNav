### Критерії приймання (приклади, за ними написано тести)

- **US-03:** після натискання «EN» назва події та підписи інтерфейсу англійською; сторінка не перезавантажується.
- **US-04:** запит `?lang=pl` для події без польського перекладу повертає англійський текст і `lang: "en"`.
- **US-05:** `GET /api/route?terminal=station&eventId=1` повертає `mode: "online"`, відстань у метрах, час у хвилинах, ламану.
- **US-06:** якщо OSRM не відповів за 5 с або повернув помилку — `mode: "fallback"`, пряма лінія, відстань за формулою гаверсинуса.
- **US-07:** без правильного `X-Admin-Key` будь-яка зміна повертає 401; подія без назви українською або з координатами поза Львовом — 400.
- **US-08:** повторний імпорт з тим самим `externalId` оновлює подію (`updated: 1`), некоректні події потрапляють у `rejected`, решта імпортується.

## 4. Інженерні практики XP у репозиторії

| Практика                       | Де видно                                                              |
| ------------------------------ | --------------------------------------------------------------------- |
| TDD (тест → код → рефакторинг) | тести в `*/test`, у git коміт `test:` з червоним тестом перед `feat:` |
| Малі релізи                    | тег у git наприкінці ітерації: `v0.1`, `v0.2`, `v0.3`                 |
| Безперервна інтеграція         | `.github/workflows/ci.yml` — lint, типи, модульні, інтеграційні, E2E  |
| Єдиний стандарт коду           | `eslint.config.js`, `.prettierrc.json`, спільні типи `shared/`        |
| Простий дизайн / YAGNI         | без зайвих фреймворків: Express, SQLite, React, Leaflet               |
| Рефакторинг                    | коміти `refactor:` після зелених тестів                               |
| Колективне володіння кодом     | будь-яка пара змінює будь-який модуль; захищає набір тестів           |
| Метафора системи               | «термінал-гід»: подія → маркер → маршрут від термінала                |
